# Optional setup call

Set SHORTLIST_BOOKING_URL to an operator-controlled public HTTPS calendar page. Blank hides the action. Credentials, local/IP destinations and non-HTTPS links are rejected. After saved company research, the optional setup call opens in a separate tab; review/export continue to work without it. No monetary price, free-call promise or calendar availability is invented.

The link includes no research, workspace identifier, email or access token, and uses noreferrer/noopener. The app records a first-party authenticated booking-link click with run ID, random request identity and timestamp. Do Not Track suppresses that optional click request; no third-party analytics library is added. Click failures do not block the calendar page. The destination calendar has its own data handling, which must be reviewed before production configuration.

Clicks are not appointments, leads, acceptance or buying intent. There is no completed-booking event or confirmed-appointment metric until a separately verified calendar integration exists. A client cannot post booked=true; only the click command is accepted. Same command key replays once, rows obey workspace isolation, and the daily click cap is100 per workspace. Clicking costs no research credits. Research deletion removes its click rows.

The hosted browser fixture uses https://cal.example/eygentic/setup-fixture and a labelled page. This proves the real link/popup/API/database behavior, not a live calendar reservation. Configure a real booking destination and test availability/confirmation on phone and laptop before launch. Human operator review and actual booking confirmation remain separate unfinished features.
