# Company name or website

Implemented and verified, 15 October 2026. User input accepts a company name, a bare public domain or a full HTTPS URL. URLs still pass the existing canonical/public-address boundary. A name cannot become an invented .com address.

Usage: Eygentic resolves directly to https://eygentic.com/ from the approved first-party brief; this case-insensitive alias is not a general name.com guess. Other company names start a saved website lookup with real checkpoints, then require choosing a matching website or entering its public URL before offer drafting and target confirmation. Search matches are suggestions, not verified legal-company identities. Prospect discovery still requires confirmed targeting.

Three approaches considered: append .com (wrong for other domains/ambiguous brands); synchronous API lookup before saving (untracked retries and lost work); the existing durable run with an unresolved company name and a guarded website selection. Choose the durable run. The website is genuinely null until selected. No placeholder domain represents an unresolved company.

Storage owns transitions: create_draft either receives a website or company name, reserves the same profiling allowance once and preserves its request identity; identity lookup is one journaled search under existing run/global caps; awaiting_confirmation at stagewebsite pauses before fetching; confirm_website is idempotent for the same URL and rejects changes after selection or stopped runs. Confirmation of offer/target is impossible without a selected website. No new SQL status or migration is needed; existing stage/checkpoint storage and ownership guards suffice.

Worker owns bounded provider dispatch and lookup replay. Candidates remain public canonical URLs, directory/seller filters share the existing adapter with optional seller exclusion for this pre-seller step. Uncertain outcomes are never automatically redispatched; unavailable/empty lookup offers manual website entry. Confirming a website neither grants new profiling allowance nor reserves company research credits. Source/model and later prospect searches keep the shared budgets.

API presents company_name and at most three dated website matches, nullable seller_url and truthful stage/events. UI owns an explicit website choice and a manual fallback, keeps names readable in saved-run navigation, and reuses the existing polling/stop/focus patterns. All URL-dependent callers must guard/narrow the unresolved variant.

Name queries quote the supplied name. Suggestions must have a relevant title or domain and exclude known directories and encyclopedia pages. The same relevance filter protects older saved matches without mutating their original journal. Empty, unrelated, failed or uncertain results offer manual website entry; unsafe provider URLs never reach the choice UI.
